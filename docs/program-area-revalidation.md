# Retained program-area revalidation

## Current generic route

Dispatch `refresh-opportunities.yml` on protected main with
`stage=program-area-revalidation`, the exact original `candidate_run`, and its
full `candidate_id`. The modern route accepts an authenticated native generation
candidate with its original maintenance reservation and spending state. It does
not accept arbitrary derived parents, qualification work, or mixed receipt and
publication selectors. The protected generation plan authenticates the actual
generation checkout separately from the workflow event SHA.

Only `scripts/extract_document_evidence.py` may differ among source dependencies;
team and embedding-semantic dependencies must remain unchanged. Preparation
revalidates the retained program-area citations without retrieving sources or
documents, extracting new evidence, or generating teams. It may remove unsupported
cached hits, but cannot add new hits or change record membership. Each affected
record can change only `topic_areas`, `document_program_areas`, and
`document_search_text`. Official facts, deadlines, descriptions, eligibility and
currentness remain intact. Removing an unsupported derived hit does not rewrite
the official notice or its proposal instructions.

The deterministic projection rebuilds catalog facets and search indexes,
metadata, the public evidence cache, `all.xml`, feed indexes, and the complete
managed topic/source-type feed inventory. Historical `changes.json` and
`changes.xml`, the source cache, scientific team outputs, and source/evidence
clocks remain unchanged. The correction has a separate audit timestamp that is
preserved on exact checkpoint resume. Normal reference and package assembly
bind the retained public data without creating a new scientific team model.

The context, reservation and public receipt use
`program-area-revalidation-modern-1`. They bind the original candidate and
manifest, generation run/attempt/SHA, producer and artifact metadata, operation
fingerprint, projection and retained hashes, consumed checkpoints, ledger hash,
and vector accounting. The child keeps its original generation identity and
records the affected correction separately in `program_area_revalidation`.

Accounting continues the original `offline-<generation-run>` ledger, including
its existing requests, conservative unknown charges, accepted responses and
sealed vector origin. The existing $2/300-request limits do not reset. A parent
vector build already accounted by the managed wrapper is authenticated without
charging its requests again. Preparation reports zero new source, document and
team requests.

An unchanged ordered corpus, configuration and vector preprocessors can retain
the exact native vector quartet only with its authenticated complete accounting
origin. The workflow then skips the vector wrapper and makes zero new Voyage
requests. A changed corpus uses the normal
`tools/run_budgeted_vectors.mjs --production --write` wrapper in reconciliation
mode against the remaining original allowance. It does not receive a separate
eight-request allowance or fabricate replacement vectors. Only that selected
vector step receives provider credentials.

Before vector dispatch the workflow uploads
`offline-ai-program-area-<parent-candidate>-reservation-<run>-<attempt>`.
Its paired `state` artifact preserves the original ledger, cached responses,
projection context, vector completion and completed child. The final private
state upload runs after candidate persistence and before the public candidate
upload; it also retains partial work after a failed vector step. Private state
does not enter the public candidate. The upload explicitly includes hidden files
so complete bundle mirrors retain `.nojekyll` and every manifest-declared path.

An older private mirror may omit a declared public file. Recovery may fill only
missing paths from an authenticated public candidate with matching declared
hashes; it never replaces corrupt existing bytes or changes a manifest. The
exact public parent can supply identical retained bytes when a child upload
failed. Missing changed bytes still require the exact public child. A repaired
mirror must pass the ordinary complete candidate loader before reuse. This
repairs transport loss without repeating projection, vectors or provider work.

If a pinned public parent artifact is missing or expired, an exact protected
publication can supply its candidate bytes. The original producer and stored
artifact pin remain unchanged; the protected pointer, canonical manifest and
every file must match. Retained native conflicts or corruption do not use this
fallback. Private reservations, ledgers and response evidence still require
their authenticated retained checkpoints.

Retries authenticate the newest paired checkpoint across the operation family;
missing, mismatched or ambiguous evidence holds recovery. A complete compatible
child is copied exactly, preserving its ID, bytes and audit time while skipping
projection, vector generation, packaging and construction. Runtime-only changes
use the ordinary named `reuse` route for that child. A further accepted extractor
change requires a new dispatch that consumes the retained accounting rather than
resetting it. Use the persisted child for downstream validation or publication
retries. The normal seven gates, exact-head review, Worker provenance checks,
protected publication, Pages and live verification remain required.

## Administrative submission dates

For a complete modern native generation, protected manual
`stage=submission-revalidation` selects only the
`administrative_submission` projection of retained evidence. It shares the
authenticated checkpoint transport but binds that distinct projection kind in
the operation, state and receipt. An absent kind retains the historical
program-area meaning; unsupported or conflicting kinds fail closed.

The projection recognizes the existing explicit source-note distinction between
an actual portal application date and a later processing close. It qualifies
only proven matching administrative events and derives their public labels,
submission selection, currentness and feeds. Source dates, original evidence, scientific
facts, source/document clocks and team outputs retain their original identity.
Whole-vector retention requires the same ordered corpus, configuration and
authenticated preprocessing contract. A changed vector dependency uses the
existing coherent builder within the original durable allowance. The original
request prefix remains exact, and only this operation's bounded vector requests
may be appended. This selector cannot make new source, document, classifier or
team requests.
