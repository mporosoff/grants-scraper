# Shared matching and researcher repair

Authority: the owner's corrective work order following inspected commit `16ed8ff1ca6e7e57199d3d4fafabeebb07f7cdb2`. This expands the former profile freeze. It does not accept Stage 3 quality, authorize a new model comparison, or authorize deployment.

| Responsibility | Existing owner and corrective integration |
|---|---|
| Canonical funding input | `GRANT_CATALOG.opportunities`, loaded through the existing catalog boundary. The matcher uses title, description, document-search text (its existing 16,000-character bound), topic areas and disciplines. The recommender neither writes nor selects a second scope synopsis. |
| Scientific query interpretation | `FUNDING_SEARCH_QUERY.tokenize`, `createAcronymResolver` and `expandGroups`, called by `FUNDING_TEAM_MATCHER.create`. Acronym resolution, word frequency and topic frequency use the complete parent or child catalog, not a singleton opportunity. |
| Selected child | `FUNDING_SUBTOPICS.loadSidecar` and `FUNDING_RETRIEVAL.createChildCatalog`. The same publishable-subject projection supplies description from the stored child summary. Exact parent/child ownership is checked against that projection. An umbrella or unavailable declared branch is not silently interpreted. |
| Currentness | `FUNDING_RETRIEVAL.recordIsCurrent`, including its submission-policy dependency. One clock is used for an action; it refreshes between actions. Both parent and selected child must remain current. |
| Canonical profiles | `researcher_registry.directory_projection`, `legacy_faculty_projection` and `matching_profiles`. All preserve the canonical summary and active claim evidence. `matching_domains` reuses `faculty_match._pi_domains` to translate source-backed claim text into the existing catalog vocabulary, retaining canonical category labels separately. These are matching facets, not new expertise claims. |
| Browser normalization | `FUNDING_TEAM_MATCHER.normalizeProfile`, called by Team Match's `directoryFacultyKey` and by the new engine for every eligible canonical person. Department and institution records receive the same representation. External/manual researcher paths retain their existing separate privacy and normalization behavior. |
| Admission | `FUNDING_TEAM_MATCHER.create(...).scoreProfile`. Its fit gate and numerical scoring formula are unchanged. The added `connections` output exposes the phrase evidence already used in that decision, matched source tokens and exact active claims. There is no independent cosine floor or quote-to-aspect admission gate. |
| Full-member contract | Every automatic or added member must have a non-null shared fit for the same scope and clock. Contract tests compare the resulting groups to `matchTeam` with its default settings. Explicit Team Match theme-chip narrowing remains a Team Match setting. |
| Semantic ordering | Existing `team-hybrid.js` continues its established Team Match role. The recommender does not reuse hosted query orchestration, send private text, or make a paid request. It uses the shared raw scientific fit, never the opportunity-recency boost. |
| Composition | `SharedTeamEngine` greedily constructs groups from every admitted seed, using max coverage of scientific tokens in the matcher's actual phrase evidence. Positive final member contribution and an existing strong scientific anchor are required; groups contain two to four people. Membership identities are deterministic; up to eight distinct alternatives are returned without padding. No Bayesian fit, new threshold search or MMR component is introduced. |
| Evidence presentation | Contributions use actual active claim labels/passages and their source URLs. Shared theme or sponsor-scope leads remain explicitly unconfirmed. A numerical fit never fills a certified role, turns an alternative into a sponsor requirement, or asserts facilities/willingness. The existing renderer, strings, controls and workflows are preserved. |
| Loading and invalidation | `OpportunityTeam.loadData` retains the asynchronous boundary. Schema 3 loads only the shared matcher and shared composition runtime plus the content-addressed public packet and existing topic sidecar. The packet binds the full canonical catalog, sidecar, directory and matcher configuration; the index pins runtime hashes. Search indexes are hashed but not duplicated in team memory. No team is calculated by the package builder or ordinary search startup. |

The old schema-2 route is rejected by the current application adapter. Its numerical assets, source-preparation tools, source-decision manifests and reports remain historical reproduction dependencies; they are not current scientific admission authorities. An exact old adapter and directory are archived under `../history/stage3-runtime/` for historical fixtures. The live static schema-1 compatibility path remains available for valid saved/manual behavior, but all existing generated teams affected by this researcher-pool repair are withheld.

The new candidate packet is deliberately not installed as the live routing index. It contains reusable input bindings, not stored teams or judge output. Its 105 canonical scope identities come from the preserved 107-scope historical inventory. Two identities lack an identical canonical parent/child projection and are reported explicitly. This is not a claim that a 150-scope rollout is complete.

Whole-pool dependency fingerprints include summaries, evidence, claim revisions, eligibility and compiled matching facets. A changed unselected candidate can change a team, so all affected pool results are invalidated. Legacy restoration, claim-retirement restoration and partial-graph reassembly cannot clear that invalidation. Old vectors and evaluation responses remain unchanged historical files; none is attached to the corrected profile text. Subsequent wording edits retire their old audit metadata, preserve history, and cannot carry unchanged source locators forward as if the new wording had been audited.

Pool assignments are retained explicitly in the canonical registry: 120 main, 35 standby and three unadmitted. Adding claims alone cannot promote the 34 standby records that would otherwise cross the old count-derived boundary. All 158 now have active evidence; the registry's historical `rankable` counter describes that fact, not automatic admission. Automatic eligibility remains 155 and all three reference-only records remain excluded.

The engine retains at most eight scope fit caches and 32 exclusion-option entries per cached scope. Action currentness and input consistency are checked before reuse; a day change clears fit caches. Returned diagnostic fits cannot mutate the cached decisions. Real Node timing remains a limitation: repeated snapshot checks are measurable even on warm edits. These observations do not establish browser latency or scientific usefulness.

No production service, workflow, permission, general-search vector, real profile eligibility, or deployment state is changed by this local correction. Separate release approval and evidence remain necessary.
