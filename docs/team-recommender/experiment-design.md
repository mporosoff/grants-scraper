### Exact nonvisual panel conflict to approve

The panel stores `current.now` once in `panelShell`, passes it in `resolveCurrent`, and directly calls synchronous engine mutations from its click handler without an error/currentness boundary. Merely adding a clock check that throws inside the engine leaves an uncaught click and stale actionable panel. Stage 2 needs a narrow orchestration exception **inside `assets/opportunity-team-panel.js`**, not a presentation rewrite:

1. `resolveCurrent`: use one fresh decision clock per resolution/action, guard package generation plus scope sequence.
2. Existing variant/remove/add/retry event branches: revalidate current source and snapshot before mutation; on expiry call the existing `renderUnavailable(current, 'not_current')`; on corruption call existing `renderFailure`. Do not alter the control, wording or DOM produced by either renderer.

This work is browser JavaScript. Stage 1 only reproduces the conflict; it does not claim the new enforcement already exists. If these nonvisual panel changes are not accepted, defer action-time currentness rather than ship a known violation.

## Input/schema and evidence policy

`ingredient-schema-proposal.json` is a record proposal, not a validator. Source identity includes parent, selected child/branch, coherent approach, material hash, locator and currentness metadata. Keep source requirements distinct from planning contributions. One approach per current selected source; ambiguous alternatives remain unprepared.

Use eligible active public claims from both main and standby pools. Keep every distinct claim under a safety bound of 16 passages/person, each at most 2,000 UTF-8 bytes; measured maximum is nine claims/person. Over-bound inputs require audited lossless chunking/grouping or unprepared status; no silent truncation. Deduplicate **exact normalized evidence within a researcher**, retaining all contributing claim IDs/revisions and URLs. Stage 1's 402-row count is a lower-bound storage estimate because semantic duplicate equivalence/linkage is not yet audited. Do not infer methods from taxonomy labels or compose method/context across unlinked claims. Public interest statements stay interests. Raw private CVs/ORCID/personal text never enter public embeddings.

Proposed vector contract: Voyage `voyage-4-lite`, 1024 dimensions; exact source aspect/core text as `query`, exact public passage text as `document`; exact UTF-8 preprocessing, no hidden provider truncation, provider float output, deterministic L2 normalization, little-endian Float32 serialization. No snapshot is available from existing manifests; pin observed document/query canaries and the complete configuration hash. Query and document roles are intentionally distinct parts of one observed space. Existing Float16 whole-call vectors are **not** substitutes for Float32 claim/aspect vectors. Float64 legacy team-cache rows could only be reused with exact text/role/space provenance and measured conversion; no such usable cache was found in inspected locations. Do not create canary requests until budget and trusted execution are separately approved.

A numerical relevance score defaults to `unconfirmed`. A claim's `direct` or `administrator_reviewed` registry evidence level does not certify a new aspect-to-person link. Direct/method-transfer coverage requires a still-current independently supported exact relation and retained claim revision. Mapping:

| Relation | filled | directEvidence | selected candidate IDs | selected alternative IDs |
|---|---|---|---|---|
| Exact reviewed direct support | true if selected | true | confirmed selected IDs | none for those IDs |
| Exact reviewed method transfer | true if selected | false | confirmed selected IDs | none for those IDs |
| Approximate useful/interest suggestion | false | false | none | selected admitted IDs |
| Missing/explicitly excluded | false | false | none | none |

`complete` means every required displayed aspect has exact supported coverage, never score/size. Optional support cannot fill central gaps. Role descriptions and actual public quotations remain escaped; URLs must pass existing protocol/host safety and provenance checks before rendering. Profile name/department are display metadata, never score features.

## Parameters, evaluation targets, and selection

No learned model or semantic threshold is selected at Stage 1. Semantic targets are primarily estimated by the fixed offline model judge, with the separate capped human audit; see evaluation-protocol.md. Preserve PLAN §8.5 targets: top-five reasonable precision >=80%; unrelated automatic member occurrences <=5%; useful primary group >=80% and group yield >=85% on independently feasible scopes; complementarity improvement over whole-call top-k at matched size with no unrelated-rate harm. Show all-case denominators, insufficient-information labels, short/empty lists, and clustered paired 95% intervals. Inconclusive superiority remains inconclusive. Zero demonstrated identity/privacy/provenance/scope-exclusion/fabricated-source failures; zero paid prepared-scope interaction requests.

Keep 200 ms cached recomputation, 1 s post-input compute, 5 s cold interactive at 20 Mbit/s/150 ms, 8 MiB transfer and 48 MiB extra heap as provisional acceptance ceilings. The measured uncompressed maximum metadata shape is slightly above 8 MiB; actual bounded encoding/compression must prove the transfer limit. No threshold is relaxed to force a pass. Node timing is an engineering cost probe, not physical-phone evidence.

Development policy to approve before tuning:

- Eight features: aspect/context similarity, core similarity, supported operation lexical overlap, supported object/context lexical overlap, specific lexical overlap, missing-operation indicator, missing-context indicator, generic-only indicator. Initially use contextual/core vectors; operation/object descriptors use source-backed phrases and lexical features so unsupported extra vector fields do not silently expand the package. Missing descriptors disable the method route. Exclusion checks use narrow explicitly parsed source conditions; negation is not a cosine rule.
- Baseline comparison arms A/B/C/D exactly as PLAN §8.3. Start B untrained with nonnegative declared weights; no probabilities. Arm A receives separately prepared whole-call/core query representations in the **same space**, matching selected size. No historical search row is relabeled as that query.
- Five grouped folds on development groups, when properly attributed machine or human development labels are available; fitting, normalization and priors never see holdout. The initial small gate grid is topic/core cosine floors `(0.30,0.25)`, `(0.40,0.30)`, `(0.50,0.35)`; those are candidates, not measured scientific cutoffs. Missing context disallows the method route; method lexical/context floors use `(0.5,0.5)` or `(0.75,0.5)` only on explicitly supported descriptors. Do not widen these grids after inspecting holdout.
- Nonnegative fixed relevance weights: contextual .5, core .3, specific lexical .2; evaluate one paired alternative .6/.3/.1. Map raw similarities to bounded features using a development-only transform, with the transform and scales locked before comparison. C uses L2 logistic `C in {0.1,1,10}`; D uses zero-centered pooled Gaussian prior SD `{0.5,1,2}`, checked deterministic Laplace integration, only with adequately attributed development labels (machine labels permitted under E1) and fit diagnostics.
- Within each source group, central/supporting/optional total budgets `.7/.3/0` by default; if an actual optional aspect exists use `.7/.2/.1`. Redistribute absent supporting budget to central. Equal weights among distinct aspects of each kind after source grouping. Optional total <=.1; split synonyms share their old group budget. Do not add optional aspects to increase objective.
- Absolute group/core floors candidate `{.45,.55}` / `{.4,.5}` and leave-one-out marginal floor `{.03,.05}`. Apply floors and scientific anchor first, then choose smallest feasible size 2–4 within 5% of best. A manual fixed member cannot create supported coverage. These dimensionless floors require development source/rubric validation; no launch claim from them alone.
- Full 155-person directory scoring before optimization; stable ASCII IDs, comparison integer `round(score*1e6)` applied once, fixed operation order, no epsilon sort. Enumerate anchored starts for every eligible anchor, one swap sweep per size initially, deterministic ceiling 300,000 coverage evaluations per requested scope/state. If growth exceeds the approved work/byte bounds, fail or report a measured seam revision; never hide candidates or take timeout-dependent best-so-far teams. Small pools require exact enumeration references in Stage 2.
- Freeze maximum aggregation against one top-two-mean alternative on development. Test exact duplicate invariance, profile passage count effects, generic text, unrelated extra passages, source/aspect reordering/splitting and missing descriptors.
- Keep the smallest near-best default first. At most eight distinct feasible alternatives within 95% of best in the same size/approach/constraint context. MMR/no-MMR paired comparison at lambda `{0,.1}` on membership Jaccard only; never admit low-quality people for diversity.
- Select the simplest arm meeting development quality/invariants; only promote C/D if grouped paired uncertainty supports an improvement in usefulness/discrimination without material unrelated-rate harm. Proper scores plus reliability bins/counts are needed for calibration claims. If development labels are missing, B can become an untrained engineering candidate; C/D remain not run. Machine-labeled fits are judged as such, not as calibrated human preferences. Freeze primary and at most one simpler fallback **before** opening holdout outputs.

## Corpus and sealed boundary

Source snapshot: `manifests/source-groups.json`, complete parent/child source hashes and currentness decision clock. `development.json` and `holdout.json` reserve 90 scientific-candidate scopes and 30 controls each. The 30 controls per side are three instances of ten predeclared perturbation categories, tied to their original source group. They are not 30 new independent real calls. Each side currently has 90 parent groups; no split overlap under recorded grouping.

Grouping unions parent ownership, same sponsor/solicitation, same official URL, year-neutral exact title and >=.85 title-token Jaccard for the same agency, before split. Deterministic salted SHA256 assigns non-exposed groups; historical team/confirmation groups are development-only. The twelve old confirmations are separately preserved in `historical-exposure.json`, not recast as fresh evidence. More subtle successor/near-duplicate and scientific coherence review is still pending. Currentness is the actual application rule on cached public inputs, not a fresh sponsor verification of every call. Source-screening keyword rules are **not** final scientific eligibility labels.

Holdout sealing is procedural and content-hashed, not encrypted: metadata/source preparation is allowed, recommendation outputs, model judgments and relevance labels are not generated or inspected in Stage 1/2. Controls are reserved but not yet materialized. Seal approval must finish the source/grouping audit before development fitting. A source rejected during that audit is documented; changing a sealed split later requires user review and retention of the earlier manifest. Do not redraw for recommendation success.

Rollout is independently selected by source/currentness/family representation, with deterministic source-only reserve order. 100 parent scopes plus 50 children, 103 actual parents; 50 first cohort is 30 parent scopes plus 20 children. The children are concentrated in three parents, and the eight family buckets are automatic source tags, not source-audited coverage of eight scientific domains. Audit this skew and replace only by predeclared source criteria before freeze. Every cohort record remains `not-prepared-or-authorized`; zero ready new scopes today. Recheck closure, publication eligibility, unsupported requirements and source revisions at release. If source criteria fail, disclose shortfalls instead of replacing based on output quality.

## Cache and runtime contract to implement in Stage 2

One immutable manifest binds engine/schema, source/approach/aspect IDs, exact claim revisions, registry generation, canaries/model roles/normalization, feature/scorer/selection versions and each asset byte length/hash. Adopt atomically at the existing reload/open boundary. No mixed old registry/new vector indices. Scope errors are scoped; search and directory remain usable. A cosmetic display edit only updates compatible display metadata. A changed/deleted claim invalidates its vector row and all affected matrices/group caches; it may change many scopes' winners. A changed source invalidates that scope's aspects and matrix; an expiry is rechecked every action even if vectors have not changed.

Propose in-memory LRU bounds: 8 matrices, 32 state/option views total, 1 atomic loaded ingredient package. Keys include matrix/scorer version, coherent approach, selected/fixed/excluded IDs, source currentness and registry/eligibility identity. No service worker, new persistent private storage, or click telemetry. Cache eviction/miss/corruption can download validated static assets or fail; it cannot call a provider. Negative no-group entries expire with their source/profile matrix identity. Retain a complete old valid package for offline rollback tests; runtime fallback only to separately current valid legacy data for that scope, never to mask a legitimate no-group result.

Stage 2 fixtures must cover source expiry between open/actions, claim retirement, excluded IDs across retries, variant identity, close/switch/late-response races, corrupt lengths/norms/hashes, unsafe source strings, saved-ID migration, manual researchers, and actual cold/static loader interception. Stage 1's mock-loader provider traps are not integrated production zero-call proof. Full real browser/E2E/Playwright work remains prohibited here and in ordinary Stage 2 work; Stage 3 needs its own explicit authorization.
