## What was wrong and what changed

The older contract serialized `outcomes_by_person` separately from contribution-edge arrays capped at four relationships per contribution. Its compact native form allowed eight total edges for two contributions; normalization still enforced four per role, alongside the generic global24 cap. Thus five returned relationships for one contribution could fail despite twelve supplied people and only 24 possible person/contribution decisions. The reported Luna failure proves that a structurally fuller answer was rejected. Its lost answer does **not** prove that every proposed relationship was scientifically valid, or which people an old model omitted because of capacity.

The repaired `contextual-complete-pairs-v1-assessment` uses mandatory person keys containing mandatory contribution keys: all 12 ×2 decisions, exactly once. More than four people can support the same contribution. Each pair has a support category, one source reference, up to three distinct owned claim references, a reason and an explicit gap. Multiple claims support one decision rather than inflating the relationship count. Overall outcomes are derived deterministically from the retained pair decisions; they are not separately generated labels that can contradict the evidence. Team size and displayed options do not enter this representation.

Hard people/pair identities and reference capacity appear in native schemas as required keyed objects with owned enums, with the same checks locally. Positive relationships require an actual owned primary claim. Wrong owners, revisions, sibling sources, duplicate keys and missing pairs are rejected. Reasons are bounded at 700 characters, gaps at 300, final answer at196,608 UTF8 bytes. The checker follows the existing Anthropic string-bound projection into descriptions plus local validation; person/pair/reference cardinalities are not prose-only constraints. The explicit pair target is a semantic/evidence-accounting version change, not a pure mechanical model-speed comparison.

The new representation is an **offline unverified assessment**, not a serving graph. Existing graph adapters, the production verifier's no-new-edge/no-upgrade behavior, composer, team size rules and successful historical schemas/caches remain unchanged. There is no partial migration or automatic consumption of the new positive labels by the browser.

Only the two named public-scientific operations opt into bounded private diagnostics. Before canonical validation or an HTTP failure, they persist status, request identifiers, completion fields, reported usage, sanitized errors and final answer text when available. Reasoning blocks, raw requests, credentials and headers are excluded. Diagnostic artifacts use the existing restricted checkpoint and 90-day retention. Diagnostics are never usable caches.
