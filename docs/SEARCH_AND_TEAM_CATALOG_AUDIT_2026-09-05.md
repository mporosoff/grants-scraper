## Findings and changes

Funding Finder and Team Match share the actual Voyage hybrid client: fielded lexical retrieval, `voyage-4-lite` document/query embeddings with 1,024 dimensions, candidate fusion, and `rerank-2.5`. The document builder uses `input_type=document`; the query Worker uses `input_type=query`. The request shapes match [Voyage embeddings](https://docs.voyageai.com/reference/embeddings-api) and [reranking](https://docs.voyageai.com/reference/reranker-api). This audit does not change the models or replace semantic retrieval with keyword scoring.

The deployed Worker smoke passed embedding, current-generation reranking, previous-generation compatibility, and rejection of an unknown corpus. The release's vector and corpus fingerprints were matched. A passing API call verifies transport and contracts, not universal semantic relevance.

Team Match already required evidence for every selected person, including within an individual child topic before parent rollup. Its semantic search nevertheless searched the entire catalog before intersecting with that evidence. The updated coordinator passes the eligible parent IDs to the shared client so unrelated calls cannot consume the retrieval budget. It also passes profile context to the local acronym resolver, includes material profile context and eligibility in its cache identity, and refuses a bounded query that would silently omit a person. Researcher names and publication text are not sent as the hosted search query.

Both local and hosted Team Match now use existing source-supported capability phrases alongside claim labels. These phrases were already in the registry; no scientific expertise was invented. The local vocabulary cache also refreshes when the same profile object changes.

Team Builder previously required exactly ten scopes, four roles, and three or four initial members. Its scope count now follows the generated manifest. New proposals support two to six source-supported planning roles and two to four members, with up to three distinct, nonredundant alternatives. Role coverage and researcher IDs determine alternatives; permutations of the same people are deduplicated. Removing someone keeps that person excluded when switching options. New eligible researchers can appear as possible replacements through their current claims, with unconfirmed role coverage kept visible.

Broad parents still open a specific child-topic selector, as in the DEVCOM example. Programs without published children are screened for a bounded scientific topic before generating anything. Each child receives only its own text; sibling or parent prose cannot establish its role quotes. A second model pass independently checks suitability and claim-to-role attribution. Deterministic validation requires exact quotes, supplied claim IDs, current eligibility, and honest gaps. Model verification cannot upgrade an adjacent claim into covering evidence.

It now opens the parent topic selector; a supported matched child still opens its own proposal. Equal-coverage teams prioritize direct scientific evidence over method transfer. Both remain available as options, with transfer support explicitly labeled and exact replacement claim evidence displayed.

Profile publication previously rejected an approved scientific change whenever a pilot team used that researcher. The revised build marks affected proposals as needing revalidation while publishing the approved profile and unaffected teams. That state survives subsequent rebuilds. New generated proposals retain exact claim revisions and material hashes; unrelated claim additions do not revoke those exact edges. ## Automatic generation

`python -m scripts.build_opportunity_teams --write` performs provider-free invalidation and projection generation. The nightly refresh runs this before a bounded generation step, so provider failure cannot silently keep newly stale proposals active.

`python -m scripts.build_opportunity_teams --generate --max-scopes 60 --workers 3 --write` processes new, changed, or invalidated scopes. It uses the existing Anthropic model configuration to decompose the source before seeing any researcher claims, Voyage document/query embeddings to retrieve current claims, and independent adjudication and verification. Only anonymous claim IDs, public scientific labels/evidence, and public opportunity text go to the model. API keys remain in the process environment. Responses are cached by exact inputs and prompts. Completed negative decisions are recorded so an ineligible first page cannot monopolize every nightly run.

Generated alternatives stay inside their opportunity, so they do not inflate search counts. Existing reviewed pilot conclusions remain the regression benchmark. Public wording does not require visitors or the owner to review every proposed team; missing expertise and unconfirmed replacement coverage remain visible.

The generation queue uses cosine similarity against current researcher claims and admits at most one topic from one parent per run. Scope vectors are cached individually, so each nightly run does not re-embed the unchanged catalog. A 15-minute soft budget and 20-minute workflow limit bound this optional step. Size checks validate both browser projections before overwriting output files.

The initial 100-scope calibration accepted 31 proposals, rejected 61 nonspecific scopes and one unsuitable scope, found insufficient evidence for two, and withheld five invalid model responses. The subsequent 20-scope semantic calibration accepted three proposals, rejected 16 nonspecific scopes, and withheld one invalid JSON response. See `evaluation/proposed_team_catalog_initial_calibration.json` and `evaluation/opportunity_team_generation.json`. The resulting catalog has **44 usable scopes across 12 parent calls**, with **104 stored team combinations**; 32 scopes have multiple stored options. One earlier surveillance proposal remains withheld after failing the independent suitability check. The lazy team projection is approximately 354 KB uncompressed.

## Coverage correction and refresh hardening

The deployed filter showed only **11 distinct calls**. The initial calibration had expanded topics mostly under DEVCOM, and the Genesis Mission parent had an available child but did not match the UI's broad-title expression. Parent navigation now follows the actual published scope index: a direct scope opens directly, while child scopes open the selector even without an umbrella phrase in the parent title. A browser contract resolves every current advertised call against its actual publication-eligible children.

Two additional batches assessed 200 scopes across distinct parents (`evaluation/team_catalog_breadth_batch1.json` and `evaluation/team_catalog_breadth_batch2.json`). They accepted 40 proposals before the subsequent fit audit. The major rejection category was nonspecific scope: 140 assessments. Broad NIH/NSF programs, training notices, and child records with too little scientific detail are not made team-ready merely because their vocabulary resembles a researcher profile. Incomplete source material remains a coverage limitation.

The fit audit found that a two-person combination could survive even when both people supplied the same role. Generated teams now require at least two covered roles and a marginal covered contribution from every member. This rule applies to initial assembly and browser-generated options after exclusions. Existing verified, unchanged evidence graphs were reassembled without new scientific assertions; 11 scopes with no complementary combination were withheld. Legacy graphs without retained individual reasons show the retained claim evidence, not an invented explanation. The resulting candidate contains **73 usable topics across 44 distinct calls, with 189 stored combinations**. This is a partial scientific catalog, not a claim that every one of the 1,551 candidate scopes fits the directory. The public lazy projection is approximately 717 KB. See `evaluation/team_catalog_complementarity.json` and `evaluation/team_catalog_refresh_readiness.json`.

The coordinated daily refresh automatically invalidates removed, closed, withdrawn, or materially changed sources before any provider work. It now assesses up to 60 topics with three concurrent workers, within the existing 15-minute soft budget. The queue prioritizes uncovered calls, reserves up to one quarter of capacity for changed existing teams, and another quarter for calls announced within 14 days. Unused reservations return to the general queue; one parent cannot consume the batch. New and changed researcher claims change the scientific pool fingerprint and queue recomputation, while departed researchers are excluded and their affected teams withheld before selection.

Generation attempt receipts now distinguish scientific decisions from provider unavailability. Truncated or malformed JSON responses stay retryable, and the output allowance accommodates the bounded role-edge schema. A previously withdrawn successful proposal cannot be permanently suppressed by its old successful attempt key when the call returns. One historical malformed-JSON rejection was explicitly requeued after matching its current input fingerprint (`evaluation/team_legacy_output_retry.json`). Source changes and scientific pool changes invalidate negative decisions as well. Parallel cache writes are atomic. Workflow summaries report distinct calls, topics, combinations, pending work, outcomes, and the generation step status, so a successful catalog refresh does not conceal a degraded optional team-generation step.

No fit threshold was relaxed to meet a count. Method transfers retain their labels and limits; absent expertise remains a visible gap. Public scientific claims and scope text are the only provider inputs, using the same existing Voyage and Anthropic services. User approval of each generated team is not required. Focused contracts cover source retirement/return, profile eligibility and claim revisions, queue fairness and recent calls, transport failures, and complementary alternatives. Required exact-head CI, review, and live verification remain release requirements.

## Validation boundary

The admin console now prepares catalog removals with a single **Remove researcher** action and no required reason. Removal is an eligibility-only patch: research claims, source dates, stable IDs, and history stay unchanged. This avoids copying incomplete public evidence metadata into the registry. Departed and inactive profiles disappear from active matching and directory search; affected proposals are withheld until regenerated. The authenticated flow uses the existing approval, revision, rebase, publication, and recovery checks. D1 migration 0004 prevents duplicate active removals and retains the administrator action in the private audit record. No actual researcher was removed during implementation.

Normal publication and post-merge recovery verify the stable researcher ID and exact generated public profile, including eligibility and evidence, against the live directory in the expected registry generation. Verification does not assume an eligibility-only removal includes a new display name. Contracts exercise removals, nominations, renamed profiles, duplicate names, stale generations, missing identities, and mismatched eligibility.

Source invalidation covers generated and curated scopes. Published children and specific parents depend on the current eligible scope fingerprint. Declared branches track their retained declaration and parent source text/URLs without admitting a broad parent to automatic generation. Missing source baselines, disappeared or ineligible calls, and material source changes withhold the affected proposal; unrelated siblings stay available. The ten initial curated baselines were registered only after comparing them with the clean-reviewed source snapshot, as recorded in `evaluation/curated_team_source_baseline.json`. All ten matched, so this correction preserves the 44 usable scopes while protecting subsequent refreshes.
